# DIOS 사용자 튜토리얼

> 비개발자가 로컬에서 프로젝트, 운영지침, Skills, Memory, Agent 작업을 관리하기 위한 사용 설명서입니다.

## 1. DIOS는 무엇인가요?

DIOS는 컴퓨터 안에 흩어진 프로젝트 자료를 한곳에서 관리하는 로컬 프로그램입니다.

DIOS가 대신 해주는 일:

- 프로젝트별 폴더·Skills·Memory 연결
- Markdown과 문서 탐색
- 프로젝트 운영지침 기록
- Phase와 Task 진행상태 관리
- Agent에게 전달할 작업 요청서 작성
- 변경 파일과 테스트 결과 확인
- SQLite 데이터 백업 및 복구

DIOS는 기본적으로 인터넷 서버에 프로젝트 자료를 업로드하지 않습니다. 저장 데이터는 이 컴퓨터의 SQLite 데이터베이스에 보관됩니다.

## 2. 설치하기

1. 배포받은 `DIOS Setup 0.1.0.exe`를 실행합니다.
2. Windows 보안 경고가 표시되면 파일 출처를 확인한 뒤 실행합니다.
3. 설치 위치를 선택합니다.
4. 설치가 끝나면 시작 메뉴 또는 바탕화면의 `DIOS`를 실행합니다.

설치하지 않고 사용하려면 배포 폴더의 `DIOS.exe`를 실행할 수 있습니다.

## 3. 처음 실행할 때의 순서

처음부터 모든 기능을 설정할 필요는 없습니다.

### 1단계: 프로젝트 만들기

1. `프로젝트 홈`으로 이동합니다.
2. 프로젝트 이름을 입력합니다.
3. `생성`을 클릭합니다.

예시:

- DIOS 자체 개선
- 나의 첫 오픈소스
- Skills 연구 노트
- 바이브코딩 프로젝트

### 2단계: 프로젝트 자료 연결

왼쪽 메뉴에서 `프로젝트 자료`를 클릭합니다.

연결 종류는 세 가지입니다.

| 종류 | 의미 | 예시 |
|---|---|---|
| 프로젝트 폴더 | 실제 소스와 문서가 있는 폴더 | `D:\MyProject` |
| Skills 폴더 | Skill 파일이 모여 있는 폴더 | `C:\Users\user\.codex\skills` |
| Memory 폴더 | Memory와 학습 기록 폴더 | `C:\Users\user\.codex\memories` |

입력 방법:

1. 연결 종류를 선택합니다.
2. 알아보기 쉬운 표시 이름을 입력합니다.
3. Windows 폴더 경로를 입력합니다.
4. `연결 저장`을 클릭합니다.

연결을 삭제해도 실제 폴더나 파일은 삭제되지 않습니다. DIOS에 저장된 연결 정보만 삭제됩니다.

### 3단계: 자료 열기

연결 목록에서 `자료 화면에서 열기`를 클릭합니다.

그러면 해당 경로를 스캔하고 DIOS의 자료 화면에서 읽을 수 있습니다.

- 프로젝트 폴더는 `자료 스캔`과 `변경사항` 확인에 사용합니다.
- Skills 폴더는 `Skills` 화면에서 읽습니다.
- Memory 폴더는 `Memory` 화면에서 읽습니다.

현재 선택된 프로젝트의 Skills·Memory 연결이 있으면 해당 경로를 우선 사용합니다.

## 4. 평소 작업 순서

권장 흐름은 다음과 같습니다.

1. `프로젝트 홈`에서 현재 프로젝트를 선택합니다.
2. `프로젝트 자료`에서 필요한 폴더를 연결합니다.
3. 필요한 폴더를 `자료 화면에서 열기`로 스캔합니다.
4. `유지보수`에서 프로젝트 운영지침을 확인합니다.
5. `Agent 요청서`에서 작업 목표와 범위를 작성합니다.
6. Agent에게 요청서를 전달합니다.
7. Agent 작업 후 `변경사항`에서 변경 파일을 확인합니다.
8. 테스트를 실행하고 결과를 확인합니다.
9. 중요한 변경 전후에 `백업·복구`에서 백업합니다.

## 5. 프로젝트 운영지침 작성하기

`유지보수` 화면의 `프로젝트별 운영지침`에 다음 내용을 적어두면 좋습니다.

```md
# 이 프로젝트 운영지침

## 작업 전
- 변경 전 백업을 생성한다.
- 현재 Phase와 Task를 확인한다.
- Skill 원본 파일은 직접 수정하지 않는다.

## 작업 중
- 지정한 폴더 안에서만 수정한다.
- 파일을 삭제하기 전 반드시 확인한다.
- 모르는 내용은 추측하지 않고 질문한다.

## 작업 후
- 변경 파일 목록을 확인한다.
- 테스트 결과를 확인한다.
- 다음 Task를 기록한다.
```

운영지침은 프로젝트별로 저장되며, Markdown 원본 파일을 자동으로 수정하지 않습니다.

## 6. Agent 요청서 사용하기

`Agent 요청서`에는 다음 내용을 구체적으로 적습니다.

- 목표: 무엇을 완성할 것인지
- 작업 범위: 어느 폴더와 파일을 대상으로 하는지
- 참고 자료: PRD, SSOT, Skill, Memory 경로
- 완료 조건: 무엇을 확인하면 완료인지
- 금지 사항: 수정하면 안 되는 파일과 행동

예시:

```md
목표: 프로젝트 홈에 현재 Phase와 다음 Task를 표시한다.

작업 범위:
- src/renderer/pages/ProjectHomeView.tsx
- src/renderer/styles/globals.css

완료 조건:
- TypeScript 오류가 없다.
- 프로젝트를 선택하면 해당 프로젝트 정보가 보인다.
- npm test가 통과한다.

금지 사항:
- API 키를 외부로 전송하지 않는다.
- 기존 Markdown 원본을 자동 수정하지 않는다.
```

DIOS는 요청서를 정리하고 보관하는 공간입니다. 실제 Agent 실행은 사용 중인 Agent 도구에서 요청서를 전달해 진행합니다.

## 7. 변경사항과 테스트 확인

`변경사항` 화면에서:

1. 연결된 프로젝트 폴더가 있는지 확인합니다.
2. `변경사항 확인`을 클릭합니다.
3. 추가·수정·삭제된 파일을 확인합니다.
4. `테스트 실행`을 클릭합니다.
5. 테스트가 실패하면 Agent에게 실패 메시지를 함께 전달합니다.

연결된 폴더가 없으면 DIOS가 임의의 폴더를 검사하지 않고 실행 버튼을 비활성화합니다.

## 8. 백업과 복구

### 백업하기

1. `백업·복구`로 이동합니다.
2. `지금 백업`을 클릭합니다.

### 보관 기간 설정하기

1. `설정`으로 이동합니다.
2. `백업 보관 정책`에서 일수를 입력합니다.
3. 설정을 저장합니다.

새 백업을 만들거나 보관 기간을 저장할 때 오래된 백업이 자동 정리됩니다.

### 복구하기

1. 복구할 백업을 선택합니다.
2. `이 백업으로 복구`를 클릭합니다.
3. DIOS가 복구 직전 상태를 안전 백업으로 먼저 보관합니다.
4. 복구 실패 시 복구 전 상태로 되돌립니다.

API 키를 DIOS SQLite에 저장한 경우 백업 파일에도 포함될 수 있습니다. 백업 파일은 다른 사람에게 전달하지 마세요.

## 9. 빠른 명령

어느 화면에서든 `Ctrl + K`를 누르면 빠른 명령 검색창이 열립니다.

검색할 수 있는 항목:

- 프로젝트 홈
- 프로젝트 자료
- 변경사항
- 유지보수
- 백업·복구
- 환경 상태
- Agent 요청서
- 자료 스캔
- Skills
- Memory
- 설정

## 10. 데이터가 저장되는 위치

DIOS의 운영 데이터는 Windows 사용자 데이터 폴더에 저장됩니다.

- 데이터베이스: `%APPDATA%\dios\dios.db`
- 백업 폴더: `%APPDATA%\dios\backups`

정확한 경로는 DIOS의 `환경 상태` 화면에서도 확인할 수 있습니다.

## 11. 문제가 생겼을 때

### 폴더가 보이지 않을 때

- 경로에 오타가 없는지 확인합니다.
- Windows 탐색기에서 해당 폴더가 실제로 존재하는지 확인합니다.
- `프로젝트 자료`에서 연결을 다시 저장합니다.
- `자료 화면에서 열기`를 다시 클릭합니다.

### Skills 또는 Memory가 비어 있을 때

- 현재 프로젝트가 올바르게 선택되어 있는지 확인합니다.
- Skills 또는 Memory 종류로 연결했는지 확인합니다.
- 해당 폴더 안에 `.md` 파일이 있는지 확인합니다.

### 테스트가 실패할 때

- 먼저 실패 메시지를 저장합니다.
- 변경사항 화면에서 어떤 파일이 바뀌었는지 확인합니다.
- Agent 요청서에 실패 메시지와 변경 파일 목록을 넣습니다.

### 데이터가 이상할 때

- DIOS를 종료합니다.
- 가장 최근의 정상 백업을 확인합니다.
- 복구 전 현재 상태가 자동으로 안전 백업된다는 점을 확인한 뒤 복구합니다.

## 12. 운영 원칙

- 중요한 변경 전에는 백업합니다.
- 한 프로젝트의 자료는 해당 프로젝트에 연결합니다.
- 원본 Skill과 Memory 파일은 읽기 중심으로 사용합니다.
- Agent에게는 목표·범위·완료 조건·금지 사항을 함께 전달합니다.
- 테스트 결과를 확인하기 전에는 작업 완료로 판단하지 않습니다.
- 모르는 것은 DIOS에 운영지침이나 Memory로 남겨 다음 작업의 재료로 활용합니다.

이 기능들은 DIOS 내부에서 로컬로 동작하며, 추가 AI 호출 없이 사용할 수 있습니다.
